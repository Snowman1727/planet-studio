# Local Project Library Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. The approved daily delivery contract authorizes implementation and normal main releases without another design approval.

**Goal:** Save, open, rename, duplicate and confirm deletion of multiple local planets.

**Architecture:** Store validated schema 2 snapshots in one versioned localStorage
document, separate from the existing recovery key. A focused library module
owns persistence; a library dialog module owns the UI. Explicit saves update an
opened entry; Save as new creates an independent entry. Recovery remains a draft
and does not silently overwrite a library entry after reloading.
Writes are asynchronous Web Locks transactions with optimistic revision checks.

**Tech Stack:** Existing JavaScript, Three.js, Lucide, native dialogs, Node 24.

**Spec:** `DAILY_PLAN.md` Day 06 and
`docs/superpowers/specs/2026-11-11-daily-delivery-design.md`.

## Global Constraints

- Only planet-studio; no blog changes, backend or new dependency.
- Preserve schema 1/2, 2,000 objects, 40 undo steps, 2 MB JSON imports.
- Preserve the existing draft key and all offline export paths.
- Both languages, keyboard, reduced motion and responsive layouts.
- Do not mark published until Actions, exact live SHA and browser checks pass.

## Decisions

- An atomic localStorage collection fits the existing draft persistence.
  IndexedDB adds migration and asynchronous transactions unnecessary for this
  bounded editor. No automatic migration or removal of the legacy draft.
- Key `planet-studio:library:v1`, document `{version:1,entries:[...]}`; entries
  contain unique IDs, ISO update times and validated project snapshots.
- Refuse all mutations if stored data is invalid or changes since the last read.
  Failed writes never update the UI's saved baseline or modify the old draft.
- Serialize mutations with Web Locks. Without safe locking, refuse writes with
  a localized HTTPS/localhost/browser/JSON-backup explanation; reads still work.
- Revalidate selected snapshots at replacement confirmation. External changes
  detach active IDs and cancel stale rename/delete confirmations.
- Renaming a stored snapshot preserves an independently edited canvas name.
- Opened-entry identity is session-only. After refresh the restored draft saves
  as a new entry, avoiding accidental overwrite of another saved project.
- A compact list shows name, environment, count and update time. No generated
  thumbnails or schema changes. Toolbar wraps at narrow widths.

## Review Focus

- A full/blocked store must preserve existing entries and the old recovery key.
- Corrupt or future-version collections must not be replaced with an empty list.
- Two tabs must not silently overwrite each other's saved collection.
- Rename/copy/delete of the opened entry must not erase current editing changes.
- User names are text, including markup and long unbroken strings.
