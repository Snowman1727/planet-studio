# PNG Image Export Implementation Plan

> Execute inline with superpowers:executing-plans and test-driven-development.

**Goal:** Export uncropped 1024/2048 square PNGs with optional transparent
background, without changing the project or editor view.

**Architecture:** Extend the existing export dialog with HTML/PNG tabs.
The shared renderer captures a square view using a cloned, sphere-fitted camera,
copies its pixels to a detached 2D canvas, and restores renderer state
synchronously in `finally` before asynchronous PNG encoding. No second WebGL
context, dependencies, persistent settings or schema change.

**Spec:** Day 02 in `DAILY_PLAN.md` and
`docs/superpowers/specs/2026-11-11-daily-delivery-design.md`.

## Constraints and Decisions

- Only the independent planet repository; existing main/push authorization
  applies. Initial clean HEAD: `e0ab4c6`, identical to fetched origin/main.
- Use Node.js 24, Three.js and native canvas PNG encoding.
- Export the displayed orientation, planet and decorations, excluding brush,
  snow particles, star backdrop and editor controls. The optional opaque
  background uses the editor's current stage color.
- Fit a conservative origin-centered sphere around terrain and visible
  instances; reserve an 8% edge margin, including tall decorations.
- Preserve renderer dimensions, pixel ratio, scene flags, preview/pause,
  world rotation, project bytes, draft, selection and undo/redo.
- PNG choices are session UI state, not world data; legacy schema 1/2 unchanged.
- HTML remains the default export tab with unchanged path and controls.
- Native size select, checkbox transparency, named download icon/button,
  roving-tab keyboard navigation, localized pending/error/success states.
- Execute inline; one final independent review per executing-plans skill.
- No Day 03 implementation; no feature is published before all gates pass.

## Review Focus

- Portrait/mobile and unusual object orientations must never crop exports.
- Failed native encoding must restore the editor and allow retry; WebGL loss
  follows the existing fatal-error route (disable PNG, retain JSON, advise reload).
- DPR > 1 must still yield exactly 1024/2048 pixels, not multiplied dimensions.
- Closing/reopening or switching tabs/languages during encoding must not lose
  state, produce duplicate downloads, or leave permanently disabled controls.
- Exporting must not write a new view to the project, erase history, or hide
  the brush/effects after restoring the render.
